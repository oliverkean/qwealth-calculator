## Calculation evidence

`src/test/fixtures/excel-scenarios.json` contains 19 scenarios recalculated using installed Excel on a disposable copy of the source workbook. Every scenario contains all 51 rows and six financial columns: **969 rows and 5,814 monetary comparisons**. Tests check both raw differences below half a cent and identical formatted cents, plus the depletion year.

The scenarios include default inputs, zero return/inflation/withdrawals, another starting balance, both lump types, negative return, early depletion, no depletion, fractional amounts, deflation, a windfall after depletion, zero balance, exact-zero closing balance, a total investment loss, tiny positive return, large amounts, and multiple events in one year.

`npm run parity` prints a summary for every scenario and sample Excel/app/difference values. `npm run parity -- --details` prints all comparisons. The extraction script prints newly recalculated JSON when supplied a local workbook path; it closes the disposable workbook without saving and removes the temporary copy.

Component tests verify that editing all four main inputs changes the displayed annual rows and the data passed to the chart. They also cover event edits and removal, invalid-input recovery, Load example, and Clear.

## Browser verification

The interface keeps explanatory copy brief. Repeated introductions, event-timing paragraphs, summary captions, chart captions, and mobile-table instructions have been removed. The event field is labelled “End of year (0–50)” instead of repeating a timing paragraph. Currency units, the annual inflation hint, nominal and today's-dollar results, no-shortfall messaging, and validation errors remain. Model timing and year indexing are explained in the README and calculation guide.

The repeatable Playwright suite in `tests/e2e/calculator.spec.ts` runs thirteen journeys at nine Chromium viewport widths (320, 336, 375, 640, 768, 1024, 1280, 1440, and 1920): 117 browser tests. It uses the production build on a dedicated port, with no mocked chart. Checks cover fresh client inputs, all six financial fields in all 51 annual rows, changes to actual chart columns and opening-value tooltips, example/clear controls, modal event editing and aggregation, focus containment/restoration, Escape/Cancel, grouped monetary inputs, bounded event lists, validation recovery, zero return, exact depletion, numeric overflow, keyboard navigation, the favicon, and page overflow. The pagination journey traverses every page against the reference values, checks boundary controls and page-size changes, and measures the gap between the chart and annual results. Each test fails on browser errors or warnings.

Run `npm run test:e2e`, then `npm run test:e2e:report` to inspect the HTML results and attached page/chart/pagination screenshots. The default configuration uses one worker. Two audit runs with the earlier two-worker configuration had browser asset-load failures (`ERR_NO_BUFFER_SPACE`); the previous complete one-worker audit run passed all 60 tests before the additional viewport projects were added. The underlying host/network cause was not established. Coverage is Chromium only; Firefox and WebKit need separate runs. Viewport emulation is not a physical-device test. The public Vercel application was also smoke-tested separately from this local browser suite.

The browser suite checks that the page's scroll width equals its available width. The fresh-input journey additionally checks all four controls against their input card's content boundaries at 320, 336, and 375 pixels, plus the existing larger viewport widths. The input grid uses an explicit shrinkable single column on narrow screens; field containers can shrink below their inputs' intrinsic widths. This prevents internal card overflow that a page-width check alone can miss. At desktop sizes, the annual projection sits in the results column directly after the chart, with a 24-pixel gap independent of sidebar height. Tables have a focusable horizontal-scroll region so all seven columns remain readable in the narrower column. Smaller screens display paginated, expandable year cards with all six financial fields.

A fresh browser scenario entered $1,000,000, 2% annual return, −1% inflation, and $8,000 monthly withdrawals, with no events. It displayed a Year 0 closing balance of $923,123.15, a balance after ten elapsed years of $203,039.28, and the first shortfall in Year 12, matching the Excel fixture. Changing monthly withdrawals to zero changed the chart columns and showed no shortfall. Clear removed all four values and the results. The optional example is loaded only by its own button.

The custom SVG favicon returned HTTP 200 with the SVG content type, and the page's icon link references it. The direct production preview had no browser warnings or errors.

## Latest local verification

The enlarged-text regression doubles the root font size to 32px at every configured viewport. It checks all sidebar action buttons against the card's content bounds, requires at least 44px target height, checks page and Year range overflow, selects all years, opens the event editor by keyboard, restores focus after Cancel, and verifies Clear.
